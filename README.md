## 这个问题是真的

DSH 的能力等于插件，插件一多就有两件事同时坏掉：

1. **模型迷茫** —— 工具清单越长，选错的概率越高。这不是玄学，是选择空间的自然结果。
2. **插件难维护** —— 什么都往一个包里塞，最后没人敢动。

官方解掉了一半，另一半还空着。空着的那半就是这里想做的东西。

开关焊在墙上了，官方自己一次都没按。因为按不按属于**策略**，不属于框架。

## 官方没给的（这里想要的）

1. **没人决定「这次任务该允许哪些工具」** —— `restrict` 是手动挡。写死在配置里就是静态子集，跟「按任务筛」是两回事。
2. **没有 `find_tools`** —— 全仓库搜索零命中。
3. **ptc 的 SDK 文本是全量的** —— 每个工具都渲染进去（`ts-types.ts:5`），工具越多那段越长，不分层。
4. **没有 miss 计量** —— 没有任何东西告诉你「能力明明存在，模型没发现」。
5. **没有能力包 manifest** —— 拆巨型插件还得手写 yml。

## 想做的事

一句话：**让工具面的宽度跟着任务走，而不是跟着配置走。**

```
        现在                             想要
┌────────────────────┐          ┌────────────────────┐
│  所有插件注册的工具 │          │  所有插件注册的工具 │
│  ┌──┬──┬──┬──┬──┐  │          │  ┌──┬──┬──┬──┬──┐  │
│  │  │  │  │  │  │  │          │  │  │  │  │  │  │  │
│  └──┴──┴──┴──┴──┘  │          │  └──┴──┴──┴──┴──┘  │
│        ↓ 全量        │          │        ↓ 按需        │
│   模型看见 200 个    │          │   模型看见 8 个      │
└────────────────────┘          └────────────────────┘
```

不是网关，不是 v2ray。**官方的派发管道已经在跑了，我们只补策略。**

一个插件，在合适的时机 `restrict({ allow: [...] })`，用完 dispose，
让 `tools/change` 去触发重组。核心逻辑大概一百行，不是一千行。

## 什么时候算成功

没有验收标准的饼就是许愿池。所以先把尺子定下来。

**先要有东西可以量：**

- 一批真实任务，**每条都标了「期望用哪个工具」**
- 这个字段是全部指标的地基。没有它，「能力存在但没被发现」永远只能靠人肉看
- 规模不用大，五十条能跑出趋势就够了

**然后是三组对照：**

| 组 | 配置 |
|---|---|
| Baseline | 全量工具全部暴露 |
| PTC | 只改一个配置项，`mode: 'ptc'` |
| Router | 按任务 restrict，干完放开 |

**必看的数字：** 任务成功率、工具选错率、额外轮次、token 消耗、延迟，
以及 **miss rate** —— 能力存在但模型没发现。这是「变脑瘫」的唯一来源。

**判据：**

- Router 比 Baseline 好 → 方向成立
- Router 比 PTC 好 → 这个项目才值得存在
- **Router 比 PTC 差 → 承认 PTC 已经够了，把这份 README 改成墓志铭**

## 这个饼的三种死法

画饼的人如果只写「想做」，不写「可能做不成」，那这个仓库就该被踩。
所以写在这里：

**死法一：PTC 组直接打到 95%。**
那 router 就是给一个不存在的缺口修水管。省下的上下文本来就不痛。

**死法二：miss rate 跟宽度无关。**
如果模型的失败模式根本不是「没看见工具」，而是「看见了也不会用」，
那收窄工具面不但没用，还可能帮倒忙 —— 因为它删掉的正是模型需要的那几个。

**死法三：检索比挑选更难。**
「该给哪八个」这件事，本身就需要一个分类器。分类器错了，
就是在模型本来能自己选对的地方，替它做了个更差的选择。

这三种都有真实概率。这里不假装没有。

## 现在到哪一步了

- [ ] 建带标签的任务集
- [ ] 跑 Baseline 和 PTC 两组，拿到第一组数字
- [ ] **这时候再决定路由器要不要写**

最后一行是关键。前面两步的产物 —— 一份带标签的任务集和一个自动算 miss 的脚本 ——
即使 router 永远不存在，它们也留着有用。

所以这个仓库最先产的，可能不是路由器，是尺子。
